# Prior-realization audit

**Script:** `Script_Bank/Analysis/SRM_AND_SBI_MONOMER_DIMER_ALP_Prior_Realization_Audit.py`
**Output:** `<data_bank_root>/Posit/<alias>_<CONDITION>_<timing>_Prior_Realization_Audit_<SPLIT>/` (report `.md` + `prior_realization_summary.json`)
**Scope:** the GENERATED products of one condition, split, and recording length — the trajectory tier's `Theta_Set`, optionally its trajectories, and the workflow's `Labeling_Set` — against the condition's prior box, the window-start composition, the stationary mode law, and the declared occupancies. It reads the products and writes only its report; nothing is simulated or rendered; seconds to run. TRAIN/TEST products are read from the split-aware root (the scratch tier on two-tier machines).

## Why it exists

The structure audit checks the generator's code against the specification. This audit checks the generator's output: whether what was actually sampled, placed, and labeled is what the prior and the declared inputs define. Run it after any tier generation or DLI pass, before the products are used for training or calibration, and re-run it whenever a range or a declared input changes. Each check is simple on purpose, so it can be read without the code and adapted to a new workflow part by adding one function over the product it reads.

Every composition below comes from the one canonical helper (`parameterization.population_from_theta`, which aligns the stored theta by key): the reference probe-bound population from the receptor total N_total and the basal reference fraction f, then, under MET-INLB, the window-start allocation of c = round(R_active × capacity) probe-bound monomer pairs into two-InlB dimers (capacity ⌊A_ref / 2⌋). Under MET-FAB the allocation is declared 0, so the starting population is the reference population.

## Checks

| check | reads | criterion |
|---|---|---|
| P0 schema | `Theta_Set` | every theta set of the tier carries the schema of the condition's biology table (ordered keys, eleven under MET-FAB and twelve under MET-INLB; prior bounds; scales; condition); the loader refuses one that does not, naming the difference, so a tier drawn under another table never reaches P1–P5. The report records the stored generator, package version, and write dates. |
| P1 prior box | `Theta_Set` | every stored theta (physical) maps back inside the condition's estimator box; per row, the twelfth included under MET-INLB, the empirical marginal in the ESTIMATOR coordinate (log10 for the log rows, the value itself for the two linear fraction rows) against Uniform(lo, hi): Kolmogorov–Smirnov p-value (a row is flagged below 0.001) and the share of draws per quarter of the box (expected 0.25 each). A flagged row is evidence to investigate (sampler, conversion, or an undersized tier), not a verdict; no scientific result shows here. |
| P2 composition | `Theta_Set` | the window-start composition realized from the stored (N_total, f) and, under MET-INLB, R_active: the represented receptor count N_R lies within 1.5 subunits of its expectation (p N_total under MET-INLB, p N_total [1 + f (3 − 2p)] / (1 + f) under MET-FAB; three roundings of half a subunit); conservation is exact through the allocation, N_R = A_ref + B1 + 2 B2_ref = A_start + B1 + 2 B2_start under MET-INLB (A + 2 D_sim under MET-FAB) with A_start = A_ref − 2c and B2_start = B2_ref + c, and B1 and the reference counts are unchanged by the allocation; 0 ≤ c ≤ capacity with c = round(R_active × capacity); c = 0 for every MET-FAB draw; M_start + 2 D_start = N_total. The median of each LINEAR row (f, and R_active under MET-INLB) lies at 0.5 within three standard errors of a uniform's sample median, 3 / (2 √n) on the unit box: the standard error width / (2 √n) follows from 1 / (2 g √n) with the uniform density g = 1 / width (the normal-median formula 1.2533 σ / √n is not the right one here and would be 28 % too tight), so the tolerance scales with the number of draws; below 20 draws this verdict is not formed. Reported beside the verdicts: quantiles of f, the capacity and c, the share of draws without a pair (capacity 0) and with an allocation, the derived starting fraction f_start and the active share c / D_start. No band and no at-least-one requirement: a draw at f = 0 holds no dimer, one at f = 1 no monomer. |
| P3 trajectories (`--trajectories K`) | K `.h5` files, evenly spaced over the tier | frame-0 particle counts per species (and per probe class B1 / B2 under MET-INLB) equal the STARTING counts the helper realizes from the stored theta, the allocation included (the report counts the opened files with c > 0); the per-frame represented subunit total is constant; the pooled frame-0 mode occupancies agree with the stationary law averaged over the K thetas within 0.03. |
| P4 labeling | `Labeling_Set` | per simulation, `n_subunits` equals the realized N_R and the frame-0 class counts equal the helper's (MET-INLB: `monomers_0` = A_start, `dimers_one_probe_0` = B1, `dimers_two_probe_0` = B2_start; MET-FAB: `monomers_0` = A and `dimers_0` = D_sim, whose one-/two-Fab classes are drawn at labeling); the recorded probe-probability columns equal the model's rule (1 for monomer subunits; (1 + s_2) / 2 under MET-FAB and 1 under MET-INLB for dimer subunits; a differing value is reported as an override, never silently); the probe classes split the dimers, with the MET-FAB two-probe share at the declared s_2 = p / (2 − p) and the MET-INLB classes exhaustive. `two_probe_share` records s_2, the declared share of the REFERENCE dimers: the share Fab labeling draws with; under MET-INLB the starting B2 share also carries the allocation and is read from the counts. The pooled fluorescent fractions are checked against q = P(dye ≥ 1) for monomers and the realized class mix for dimers (q for a one-probe dimer, 1 − (1 − q)² for a two-probe dimer); the share of fluorescent dimers with both subunits labeled against the two-probe dimers' q²; the labeled subunits and the emitters per subunit against q and E[dye] times the probe-bound share; each within max(0.02, three standard errors). |
| P6 visibility | nothing on disk (both conditions, always) | the theoretical visibility chain of the represented population corroborated through the DLI stage's own labeling path (`resolve_labeling`, `label_subunits`: `assign_probes`, `draw_dye_counts_bound`, `labeling_summary`) on a synthetic frame-0 lineage of 10⁵ monomers and 10⁵ dimers per condition (B1 / B2 at the declared two-probe share under MET-INLB; B hosts classed at labeling under MET-FAB): fluorescent monomers q, one-probe dimers q, two-probe dimers 1 − (1 − q)², the share of fluorescent two-probe dimers with both probes fluorescent q / (2 − q), the MET-FAB two-probe share s_2, the emitters per bound probe E[dye], and the dye-count law among labeled subunits (the zero-truncated law, binned 1 / 2 / ≥ 3), each within four standard errors; the rule the code path recorded equals the declared one. Across the two conditions, the FAB/INLB visibility ratio of the underlying population, p q, is checked against the DECLARED visibility ratio (tolerance 0.05) and shown beside the deposited spot-count ratios (A9: first-2 s medians, whole-recording means, per area). |
| P5 predictive fluorescent counts | `Labeling_Set` + the A9 first-2 s spot counts of the 60 deposited recordings per condition (embedded in the script; the Special_Analyses CSV takes precedence when present) | fluorescent hosts at frame 0 per simulation against those counts: quantiles side by side and the share of recordings inside the simulated range. DESCRIPTIVE: the simulated count is before bleaching, detection, and field-of-view effects; judged only for gross mismatch (the empirical median inside the simulated 5–95 % band). |
| P7 campaign membership (`--campaign-version V [--expected-tasks N] [--task-simulations M] [--campaign-window A..B]`) | the tier's `Theta_Set` schema, the detector's own `Theta_Set` schema under `--workflow detector`, the workflow's `Labeling_Set` | every expected task 0..N−1 is present (a task beyond N is reported, never selected for training); every task's theta sets carry in their schemas package version V, the run's condition and timing label, the generators `rds` and `dli_detector` and a written time inside A..B, with M rows; every task's `Labeling_Set`, which carries no version or time, has the thirteen columns, M rows, the declared per-class probe probabilities and two-probe share (the `classes` rule, not an override). The schema guard compares keys, bounds, scales and the condition, records the package version without comparing it and inspects no video, so an earlier generator's detector dataset under the same imaging box passes it; this inventory establishes campaign membership instead (`DETECTOR_WORKFLOW.md` §9.10). Run after the render pass, when the detector theta sets and labeling sets exist. A failing task excludes the dataset from training until it is regenerated |

The report ends with a three-column visibility table — theory from the declared settings, the DLI code path on the synthetic lineage, and (when a `Labeling_Set` is present) the generated products — so the theoretical visibility is corroborated at both levels on one page: the functions the DLI stage calls realize the closed forms, and the products the stage wrote realize them too.

`--selftest` draws synthetic products from each condition's prior in memory, realizes each draw through the canonical helper, labels it through the same DLI functions from its STARTING counts, and runs P1, P2, P4, P5, P6 on them, so the checks themselves are verified without a tier on disk; it also requires that some MET-INLB draws carry an allocation (c > 0) and that no MET-FAB draw does, so the allocation is exercised through the labeling path. `--visibility` runs P6 alone for both conditions (theory versus code path), the quickest way to see the visibility chain the declared settings imply. Both modes write under the data bank's Posit directory unless `--out-dir` names another folder.

## Reading the report

A P1 or P2 FAIL is a defect in sampling, conversion, or the composition helper and blocks the tier. A P3 FAIL is a placement, seeding or lineage defect: the frame-0 counts are compared with the starting counts, so an initializer that places the reference instead of the allocated population shows here. A P4 FAIL is an occupancy, labeling or placement defect, or an unrecorded override. A P6 FAIL means the DLI stage's labeling functions do not realize the closed-form visibility of the declared settings — a code defect, since no product is involved; a visibility-ratio FAIL means the derived FAB occupancy no longer yields the declared ratio to the INLB anchor. P5 is a sanity check of the prior against the data, not a test the model can fail by being wrong about biology: a gross mismatch means the count range or the occupancy convention does not put the simulated fluorescent population where the recordings are.
