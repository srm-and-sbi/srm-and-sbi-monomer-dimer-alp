# Prior-realization audit

**Script:** `Script_Bank/Analysis/SRM_AND_SBI_MONOMER_DIMER_ALP_Prior_Realization_Audit.py`
**Output:** `<data_bank_root>/Posit/<alias>_<CONDITION>_<timing>_Prior_Realization_Audit_<SPLIT>/` (report `.md` + `prior_realization_summary.json`)
**Scope:** the GENERATED products of one condition, split, and recording length — the trajectory tier's `Theta_Set`, optionally its trajectories, and the workflow's `Labeling_Set` — against the prior box, the composition rule, the stationary mode law, and the declared occupancies. It reads the products and writes only its report; nothing is simulated or rendered; seconds to run. TRAIN/TEST products are read from the split-aware root (the scratch tier on two-tier machines).

## Why it exists

The structure audit checks the generator's code against the specification. This audit checks the generator's output: whether what was actually sampled, placed, and labeled is what the prior and the declared inputs define. Run it after any tier generation or DLI pass, before the products are used for training or calibration, and re-run it whenever a range or a declared input changes. Each check is simple on purpose, so it can be read without the code and adapted to a new workflow part by adding one function over the product it reads.

## Checks

| check | reads | criterion |
|---|---|---|
| P0 schema | `Theta_Set` | every theta set of the tier carries the current biology table's schema (ordered keys, prior bounds, scales, condition); the loader refuses one that does not, naming the difference, so a tier drawn under another table never reaches P1–P5. The report records the stored generator, package version, and write dates. |
| P1 prior box | `Theta_Set` | every stored theta (physical) maps back inside the estimator box; per row, the empirical marginal in estimator space against Uniform(lo, hi): Kolmogorov–Smirnov p-value (a row is flagged below 0.001) and the share of draws per quarter of the box (expected 0.25 each). A flagged row is evidence to investigate (sampler, conversion, or an undersized tier), not a verdict; no scientific result shows here. |
| P2 composition | `Theta_Set` | from the stored (N_R, r): every draw realizes at least one dimer; the realized receptor fraction follows x_B = 2r / (1 + 2r) up to half a dimer of rounding; the median of the requested log10 ratio lies within three standard errors of the box center, the standard error of a uniform's sample median being width / (2 √n), from 1 / (2 f(m) √n) with the uniform density f = 1 / width (the normal-median formula 1.2533 σ / √n is not the right one here and would be 28 % too tight), so the tolerance scales with the number of draws (a fixed tolerance on the complex fraction would fail a correct sampler at small n, since f_B moves by about 0.58 per dex near an even split); the realized f_B median is reported beside it. Below 20 draws the symmetry verdict is not formed. |
| P3 trajectories (`--trajectories K`) | K `.h5` files, evenly spaced over the tier | frame-0 particle counts per species equal the composition realized from the stored theta; the per-frame subunit total is constant; the pooled frame-0 mode occupancies agree with the stationary law averaged over the K thetas within 0.03. |
| P4 labeling | `Labeling_Set` | `n_subunits` equals round(N_R) per simulation; the recorded occupancy columns equal the condition's declared or derived value (a differing value is reported as an override, never silently; whether it was intended is for the reader); the pooled per-subunit visibility `n_labeled_subunits / n_subunits` against a = p_occ · P(dye ≥ 1); pooled visible fractions against a for monomers and 1 − (1 − a)² for dimers; the share of visible dimers with both subunits labeled against a / (2 − a); the emitters per subunit `n_dyes / n_subunits` against p_occ · E[dye]; each within max(0.02, three standard errors). |
| P6 visibility | nothing on disk (both conditions, always) | the theoretical visibility chain corroborated through the DLI stage's own labeling functions (`draw_dye_counts`, `occupancy_per_subunit`, `labeling_summary`) on a synthetic frame-0 lineage of 10⁵ monomers and 10⁵ dimers per condition at the declared occupancy: per-subunit visibility a, visible monomers a, visible dimers 1 − (1 − a)², both-labeled share a / (2 − a) (visible dimers with both subunits labeled; for INLB also the two-dye share), dark-partner share 2(1 − a) / (2 − a), emitters per subunit p_occ · E[dye], emitters per visible subunit E[dye] / P(dye ≥ 1), and the dye-count law among visible subunits (the zero-truncated law, binned 1 / 2 / ≥ 3), each within four standard errors; the occupancy the code path recorded equals the declared one. Across the two conditions the realized FAB/INLB per-subunit visibility ratio is checked against the DECLARED visibility ratio (tolerance 0.05) and shown beside the deposited spot-count ratios (A9: first-2 s medians, whole-recording means, per area). In a products run the same ratio is also formed from the two conditions' `Labeling_Set`s when both exist at the run's timing, split, and workflow. |
| P5 predictive visible counts | `Labeling_Set` + the A9 first-2 s spot counts of the 60 deposited recordings per condition (embedded in the script; the Special_Analyses CSV takes precedence when present) | visible hosts at frame 0 per simulation against those counts: quantiles side by side and the share of recordings inside the simulated range. DESCRIPTIVE: the simulated count is before bleaching, detection, and field-of-view effects; judged only for gross mismatch (the empirical median inside the simulated 5–95 % band). |

The report ends with a three-column visibility table — theory from the declared settings, the DLI code path on the synthetic lineage, and (when a `Labeling_Set` is present) the generated products — so the theoretical visibility is corroborated at both levels on one page: the functions the DLI stage calls realize the closed forms, and the products the stage wrote realize them too.

`--selftest` draws synthetic products from the prior in memory, labels each composition through the same DLI functions at the declared occupancy, and runs P1, P2, P4, P5, P6 on them, so the checks themselves are verified without a tier on disk. `--visibility` runs P6 alone for both conditions (theory versus code path), the quickest way to see the visibility chain the declared settings imply.

## Reading the report

A P1 or P2 FAIL is a defect in sampling, conversion, or the composition rule and blocks the tier. (The first products run of 2026-09-14 produced a P2 FAIL on the FAB TRAIN tier from a fixed 0.05 tolerance on the f_B median at 250 draws, 1.3 standard errors off center while P1 passed on the same row; the tolerance was made to scale with n the same day, first with the normal-median formula and then, after a second external review, with the uniform-median formula, and the tier passed on re-audit under both.) A P3 FAIL is a seeding or lineage defect. A P4 FAIL is an occupancy or labeling defect, or an unrecorded override. A P6 FAIL means the DLI stage's labeling functions do not realize the closed-form visibility of the declared settings — a code defect, since no product is involved; a visibility-ratio FAIL means the derived FAB occupancy no longer yields the declared ratio to the INLB anchor. P5 is a sanity check of the prior against the data, not a test the model can fail by being wrong about biology: a gross mismatch means the count range or the occupancy convention does not put the simulated visible population where the recordings are.
